# 議事録（基本版）

妙記の逐字録を根拠に、読む人が短時間で「何が決まり、次に誰が何をするか」を理解できるLark Docを1つ作る。

## 設定

使う人が自分に合わせて書き換える。指定がなければこの既定値で動く。

| 項目 | 既定値 | 説明 |
|---|---|---|
| サマリーの作り方 | `画板` | `画板`＝Larkの画板で作る（追加の道具不要）。`手描き`＝画像生成で手描き風に作る（Codexの画像生成などが使える環境のみ。使えなければ自動で `画板` に切り替える） |
| メインカラー | `緑` | 決定事項の箱や見出しの差し色。`緑`＝green／`青`＝blue／`紫`＝purple／`橙`＝orange（Docの色指定にはこの英語名を使う） |
| 文字起こしの保存 | `する` | `する`＝逐字録をmdにしてLarkのマイスペースへ保存。`しない`＝保存しない |
| 保存先フォルダ | （空） | Docとmdを置くLarkフォルダのURL/token。空ならマイスペース直下 |

## 開始前に読む

lark-cliの公式スキルを読んでから始める（コマンドの書き方・認証・Docの書き方が書いてある）。

```bash
lark-cli skills read lark-shared
lark-cli skills read lark-meeting
lark-cli skills read lark-doc
```

Docに画板を入れる前に、次の2つも読む。

```bash
lark-cli skills read lark-doc references/lark-doc-xml.md
lark-cli skills read lark-doc references/lark-doc-whiteboard.md
```

## ワークフロー

### 1. 妙記を特定する

- 貼られたURLから妙記のtokenを取り出す（`.../minutes/<token>` の末尾）。
- URLが無ければ自分の最近の妙記を検索し、タイトルと日時を見せて選んでもらう。

```bash
lark-cli minutes +search --owner-ids me --page-size 10 --as user --json
```

- 見る権限が無い妙記なら、勝手に申請せず「閲覧権限がありません。申請しますか？」と確認してから `minutes +apply-permission` を使う。

### 2. 逐字録を取得する

AI要約だけで作らない。必ず逐字録を取り、決定・担当・数字・期限を照合する。

```bash
lark-cli minutes +detail --minute-tokens <token> \
  --transcript --todo --chapter --as user --format json
```

- 逐字録はJSONには入らず、カレントディレクトリの `minutes/<token>/transcript.txt` に書き出される。それを読む。
- 会議の日付はこの出力に入らない。`lark-cli minutes minutes get` の `create_time` で確かめる（逐字録の1行目も参考にする）。
- 妙記の題が「〇〇 のビデオ会議」のような汎用名なら、内容から会議名を付ける（Docとmdの名前に使う）。

### 3. 文字起こしを保存する（設定が `する` のとき）

逐字録だけをmdにして保存先へアップロードする。ファイル名は `【YYYY-MM-DD】<会議名>_文字起こし.md`。`drive +upload` の `--file` は相対パスで渡す（mdを置いたフォルダに移動してから実行する）。**Doc本文には文字起こしを入れない。**

### 4. 素材リストを作る

逐字録から次を抜き出す。推測と事実を混ぜない。

- 会議名・日付・参加者・目的
- 論点・現状の課題
- 決定事項（明言されたものだけ）
- ToDo（担当・内容・期限。明言が無ければ「未定」。「次回の3日前ごろ」のような言い方は日付に直さず、そのまま書く）
- 数字・日付・固有名詞・条件
- 未確定事項・リスク（提案・検討案・目安の金額はここ）

この素材リストを、サマリー・決定事項・図解・フローの共通の元にする。要約をさらに圧縮して使い回さない。

### 5. 1枚サマリーを作る

Docの冒頭に16:9の1枚サマリーを必ず入れる。作り方は `references/summary.md` に従う。

- `画板`：SVGの画板を、Docの概要の直前に入れる
- `手描き`：画像を生成し、目視で誤字を確認してから `<img path="@./summary.png"/>` で入れる。画像生成が使えない環境では `画板` で作る

### 6. Lark Docを作る

タイトルは `【YYYY-MM-DD】<会議名> 議事録`（日付＝会議の日）。構成は次の順にする。

1. 録画リンク（妙記URL）
2. 1枚サマリー
3. 概要（日時・参加者・目的・3行まとめ）
4. ✅ 決定事項
5. ToDo（表：担当／内容／期限）
6. 図解・チャート（効くときだけ）
7. 次のステップ（フロー図・必須）
8. 未確定事項・リスク
9. 参考情報（文字起こしmdのリンクなど）

長いDocは骨格を先に作り、章ごとに追記する。

#### 決定事項の箱

1つの決定につき1つの箱にする。メインカラーの淡い色のcalloutを使う（下の例は `緑` のとき。`青` なら `light-blue` と `blue`）。

```xml
<callout emoji="✅" background-color="light-green" border-color="green">
  <p><b>決定の核になる語句</b>を含む1文。理由・条件があれば1〜2文で続ける。</p>
</callout>
```

- ✅は箱のアイコンの1個だけ。本文の先頭に✅やチェックボックスを付けない（二重になるため）
- 決まっていない提案・検討案は入れず、「未確定事項・リスク」へ回す
- 言い換えただけの重複した箱を作らない

### 7. 図解・チャートを入れる（効くときだけ）

文章より図のほうが早く分かるときだけ入れる。図にしても情報が増えないなら章ごと省く。種類の選び方は `references/diagrams.md`。

- チャートは**逐字録に出てきた数字だけ**で作る。数字を作らない・補わない
- 空の画板を残さない

### 8. 次のステップをフロー図で入れる（必須）

テキストの一覧だけで済ませない。Mermaidの横向きフローの画板にする。

```xml
<whiteboard type="mermaid">
graph LR
  A["担当A：準備（〜11/5）"] --> C["次回MTG"]
  B["担当B：見積もり"] --> C
  C --> D["実施の判断"]
</whiteboard>
```

- 1つの箱の文字は12文字前後までにする。長いと単語の途中で勝手に折り返される（「分／割」など）。2行にしたいときは、言葉の切れ目に `<br/>` を自分で入れる
- 並行するタスクは枝分かれさせ、次回MTGや意思決定で合流させるフローの下に詳しいToDoを書いてもよい。

### 9. 仕上げを確認する

作ったDocを取り直して（`docs +fetch`）、次を確認してから完成と伝える。

- サマリーが表示され、文字が崩れていない（画板を書き出したプレビューは正方形で、下に余白が出る。これはプレビューの仕様なので、中身の崩れだけを見る）
- 決定事項が1箱1決定で、✅が二重になっていない
- 決定事項と未確定事項が混ざっていない
- 担当・期限・数字に作り話が無い
- 次のステップが横向きのフロー図になっていて、箱の中で単語が途中で切れていない
- 空の画板が無い
- タイトルの日付が会議の日と一致している
- 文字起こしの全文がDoc本文に入っていない

最後に、DocのURLを1行で伝える。決定事項の箱の色は取り直しでは確かめられないため、「緑の箱になっているか、画面で一度見てください」と添える。
